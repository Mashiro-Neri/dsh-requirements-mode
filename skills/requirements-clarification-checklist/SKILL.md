# 阶段 C：容易遗漏的检查维度

先识别项目属于哪些类别，再**只挑真正相关的**维度提问。一次只问最影响当前决策的少量问题；不相关的类别不要强行询问。

## 一、按项目类型

| 项目特征或风险 | 应主动考虑的细节 |
|---|---|
| 数据、账号或第三方服务 | 数据来源可靠性、读写边界、授权范围、隐私、费用、配额、失败与迁移方案 |
| 自动化、同步或后台任务 | 触发方式、频率、幂等性、重复执行、失败重试、离线行为、状态可见性、手动干预入口 |
| 桌面、移动端或常驻应用 | 启动与退出行为、前后台状态、通知、系统资源、焦点、窗口布局、多设备或多屏幕环境 |
| 网站、表单或业务工具 | 用户角色与权限、核心路径、空状态、错误状态、筛选搜索、数据量、响应式布局、无障碍 |
| 内容、创作或展示产品 | 目标受众、信息层级、素材来源与版权、编辑流程、导出分享、不同屏幕下的阅读体验 |
| 文件处理、导入导出或脚本 | 输入格式、异常文件、数据丢失风险、备份、可重复运行、输出位置、进度与取消机制 |
| 硬件、系统设置或高风险操作 | 权限提升、不可逆操作、兼容性、回滚、恢复路径、用户确认与安全提示 |
| 性能敏感或长期运行 | 资源预算、启动速度、网络与磁盘影响、数据规模、性能退化、监控或日志需求 |
| 依赖用户素材或配置 | 谁提供什么、格式与质量要求、何时提供、缺失时的占位或降级、敏感信息的交付方式 |

## 二、每类项目都要问的横切项

- **状态完整性**：成功、空数据、加载中、失败、权限不足、配置缺失，各是什么表现。
- **交互恢复**：误触如何防、能否撤销、撤销后回到什么状态。
- **模糊词落地**：把"简单""实时""好看""轻量""自动"换成可观察、可验收的定义（例如"实时"= 几秒内？"轻量"= 内存/包体上限？）。
- **影响面**：哪些决定会牵动成本、隐私、维护难度或后续扩展。
- **素材依赖**：谁提供、格式与质量要求、何时提供、缺失时如何降级、敏感信息怎么交付。

## 三、不要做的事

- 不要套用固定问卷：不相关的类别不提。
- 不要把这份表的全部维度一次性倒给用户。
- 不要用"要不要做得更好"这类伪问题凑数。
