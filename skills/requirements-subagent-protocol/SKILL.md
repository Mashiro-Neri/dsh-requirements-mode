# 子 Agent 操作协议

本技能是操作手册。原则与流程骨架在常驻说明里，这里只讲"具体怎么调"。

## 一、共同点

两个子 Agent 都配了 `continuable` 模式：

- 调用时**不要设 `run_in_background: false`**（省略即可）。省略或设 `true` 会返回 `started subagent <childId>`，那个 id 就是后续派活的地址；设成 `false` 只会同步返回文本、**丢掉 id**，这个子会话之后就找不回来了。
- 它的最终文本**不是同步返回的**，而是这一轮跑完之后作为**收尾通知异步到达**。所以节奏是：派活 → 等它在对话里回报 → 再派下一条。
- **它正在跑的时候不可投递。** 此时 `send_message` 返回 `Error: subagent "<id>" is unavailable`。这不是故障，等它这一轮结束（收到回报）之后再发即可，**不要在运行中反复重试**。
- 它们**看不到你和用户的对话**，所以每次创建都要把背景讲全；之后每一轮派活仍要写清那一轮的问题，不要只说"再查查"。

派活统一用：

```
send_message(agent_id: <childId>, message: ...)
```

参数名是 **`agent_id`**。如果你看到参数是 `target`，那是**另一个工具**（Agent Teams 插件的），它只服务队友、发不到这里——把这条报给用户，让他关掉那个插件；同时改用 `agent_id` 重试一次。

## 二、调查员 `subagent_explore`

职责：回答"这台机器 / 这个代码库实际是什么样"。它有 shell，也有 write / edit（备用）。

派活前先自己判断：**一句话能问清的，自己跑只读命令就行，别绕子 agent**。要翻很多文件、要多步骤、或需要独立视角时再委派。

交给它的调查计划要包含：要回答什么问题、看哪些文件或跑哪些命令、要求给出原始证据。

它回来之后：核对**原文证据**（读了哪个文件的哪一段，或跑了哪条命令及其原始输出），不要只看结论。它标注为"推断"或"未能确认"的内容要降级处理——**它标为推断的东西，你要么自己核实，要么留给用户核实，不要直接当事实用。**

## 三、复核者 `subagent_review`

职责：对开发文档草稿做对抗式证伪。它看不到讨论过程，所以拿不准的会列成"待澄清"而不是瞎判。

调用时一次把四样东西交全：

- 草稿全文（不贴等于没给它材料）
- 用户的原话要点（尤其是每条"已确认项"对应哪次答复）
- 你的确认台账
- 调查员带回的真机事实

拿到报告后，先对话再回报用户：用 `send_message` 把你能给的具体依据（用户原话、当时的选择、现场约束）告诉它，它必须逐条回"撤回（理由成立）"或"维持（缺的是 X）"。**给它理由，不要只坚持结论**——拿不出依据的坚持，它会维持并升级为阻断。同一条意见最多来回两轮。

## 四、报错对照

| 报错原文 | 含义 | 怎么办 |
|---|---|---|
| `tools.restrict() names unknown global tool(s) "..."` | 子 Agent 的工具白名单里写了本作用域不存在的名字 | 改动 `cordis.patch.yml` 的两处 `allow`；跑 `node scripts/check-tool-filter.cjs` 复验 |
| `subagent "<id>" is unavailable` | 它正在跑 | 等这一轮结束再发，不要重试 |
| `active teammate "<id>" not found` | 调到了 Agent Teams 的同名工具（参数是 `target`） | 改用 `agent_id`；并提醒用户关掉那个插件 |
| `agent "<id>" is not a resident continuable child and cannot send to parent` | **子 agent 想主动推消息给父级**。子只在"正在跑"时留在运行时表里，跑完就退出 | 这是运行时的方向限制，**不是故障**。它的结果会通过收尾通知正常送达，**不要试着修**，也不要因此判定环境有问题 |
| 创建直接失败且没有明确报错 | preset 可能整体挂了 | 让用户去 设置 →「模式」看那张卡片上的"加载失败"原因——那是唯一能看到错误文本的地方 |
