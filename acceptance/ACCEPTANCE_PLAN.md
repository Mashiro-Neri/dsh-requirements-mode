# 验收计划（模板）

> 项目： · 版本： · 日期： · 编写者： · 复核者：

把这份填完，才能说"可以交付"。验收不是再看一遍文档，是逐条证明它在真实环境里成立。

## 一、风险分级

| 范围 | 级别 | 命中规则 | 用户确认原话/时间 |
|---|---|---|---|
|  | L0 / L1 / L2 / L3 |  |  |

- L0 文档级 · L1 普通功能 · L2 迁移/部署/配置/权限/成本/外部副作用 · L3 删除/密钥/生产重启/不可逆
- 命中高风险路径（迁移、鉴权、部署、密钥、数据、配置）最低 L2；删除与不可逆最低 L3
- 拿不准就升一级；拆成多个任务不降级

## 二、验收矩阵

每条写 `操作/命令 → 期望可观察结果 → 环境 → 通过阈值`，禁止"正常/流畅/不变/已确认"。

| 类别 | 场景 | 操作/命令 | 期望结果 | 环境 | 结果 | 证据 |
|---|---|---|---|---|---|---|
| 正常路径 |  |  |  |  |  |  |
| 空态 |  |  |  |  |  |  |
| 加载中 |  |  |  |  |  |  |
| 失败 |  |  |  |  |  |  |
| 权限不足 |  |  |  |  |  |  |
| 超时 |  |  |  |  |  |  |
| 无人在场 |  |  |  |  |  |  |
| 未知结果 |  |  |  |  |  |  |
| 断网 |  |  |  |  |  |  |
| 重启/重连 |  |  |  |  |  |  |
| 跨设备/跨版本 |  |  |  |  |  |  |
| 性能 | p50 / p95 |  |  |  |  |  |
| 缓存 | 真实命中 |  |  |  |  |  |
| 审计 | 日志/事件 |  |  |  |  |  |

不适用的行写 `N/A + 原因`，不要空着，也不要静默跳过。

## 三、状态语义

对每个会失败或会等待的操作，写清七个字段：

```text
状态 / 原因码 / 是否可重试 / 用户是否在场 / 用户文案 / 模型文案 / 审计记录
```

副作用另加五个字段：`approval_state`、`effect_state`、`retryable`、`idempotency_key`、`unknown_outcome`。

必须区分：无人在场 ≠ 用户拒绝；超时 ≠ 拒绝；未知 ≠ 失败；离线 ≠ 不存在；审批未送达 ≠ 策略拒绝；没开始 ≠ 已执行。

## 四、证据

每条验收至少一种，优先前面的：

1. 原始命令输出（含 exit code、时间、环境）
2. 日志/事件序列（路径 + 时区 + 起止）
3. 真机截图（必须带目标身份：窗口标题 / URL / 记录 id）
4. 可重复脚本
5. 失败注入记录（超时、断网、并发、重启至少一种）

禁止：只说"代码写完"、只看单测、只看截图局部、用自算 hash 冒充缓存命中、用"应该可以"代替真机。

## 五、判定

- 状态只能是：`verified` / `demo` / `awaiting-user` / `known-issue` / `blocked`
- **`verified` 只能由独立验证者写**；实现者最高 `demo`
- 用户可见的变更，还要用户自己看到结果并留下原话，否则最多 `awaiting-user`
- 未验证项与已知风险逐条列出，不要合并成一句"其余正常"
